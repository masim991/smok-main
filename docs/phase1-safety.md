# Phase 1 정확성/안전 결과

기준: `336abd42e9a5b3e777faf2c7673a9c3f46e4ffa7`. Phase 0의 4개 실패를 먼저 수정하고 날짜·목표·통계·동기화·계정 삭제 테스트를 확장했습니다.

## A. 변경과 이유

- `lib/recordMetrics.ts`, `lib/historyMetrics.ts`, 기록·목표·통계 화면: UTC 저장 시각을 현지 달력 날짜로 집계. 미래 날짜와 불완전한 오늘을 금연 완료일로 세지 않고, 빈 기록의 통계는 0으로 계산.
- `lib/syncPolicy.ts`, `components/contexts/DataContext.tsx`, `LocalMemoryStorage.ts`: 계정별 스냅샷, 대기 작업, 동일 ID 재시도, 충돌 보존, 오류 표시, 저장 실패 전파. 공용 로컬 키는 원본으로 남기고 설정에서 명시적으로 복사.
- `contexts/AuthContext.tsx`: Supabase 인증 응답 오류를 처리. 계정 삭제는 서버의 정확한 확인 응답 후에만 성공 처리.
- `app/(tabs)/goals.tsx`와 번역: 기준 흡연량 또는 근무 일정이 없어서 계산할 수 없는 네 템플릿을 새 선택 목록에서 제외. 기존 목표는 보존하고 수동 완료로 표시.
- `app/(tabs)/history.tsx`: 흡연 기록만으로 계산할 수 없는 절약액·회피 개비 추정을 관찰 가능한 일수로 교체.
- 테스트·lint/타입 기준 오류 수정: Phase 0 실패를 통과시키고 기존 타입 오류 2건과 lint 오류 4건을 해결.

## B. 호환성과 롤백

`@SmokeTracker:entries`, `@SmokeTracker:goals`, `@SmokeTracker:supabase-auth` 키와 기존 원본 기록은 삭제하지 않습니다. 계정별 신규 키는 별도로 생성되며 다른 계정 화면에 이전 계정의 로컬 기록을 표시하지 않습니다. 새 기능 커밋을 되돌리면 기존 키의 기록은 남지만 신규 계정별 키의 기록과 대기 작업은 구버전 앱에서 보이지 않습니다. 따라서 실제 사용자에게 롤백할 때는 해당 키를 백업하고 데이터 복원 절차를 검증해야 합니다. 서버 변경은 적용하지 않았습니다.

## C. 검증

| 명령 | 결과 |
| --- | --- |
| `npm ci` | Phase 0 잠금 파일에서 성공. Phase 1에는 의존성을 추가하지 않음 |
| `npm run typecheck` | 통과 |
| `npm run lint -- --quiet` | 통과 |
| `npm test` | 29개 통과 (최종 실행 결과 확인 후 갱신) |
| `npm run build:web` | Phase 0의 네이티브 지도 import 실패가 남아 있음. 웹 범위는 README 참조 |

Android/iOS 실제 기기 검증은 이 Windows 환경에서 수행하지 못했습니다. 특히 계정 전환, 장시간 오프라인, 백그라운드 권한, 서버 RLS는 실기기·테스트 서버 검증이 필요합니다.

## D. 성능

변경 전후 기기 성능 수치는 없습니다. 실행 가능한 Android/iOS 기기와 서버 요청 계측이 없어 임의 수치를 제시하지 않습니다. Phase 2에서 동일 기기·계정·지도 영역으로 위치 구독 수, 분당 위치 콜백, Supabase 요청 수, 화면 렌더 횟수 및 긴 목록 스크롤을 변경 전후 각 3회 측정합니다.

## E. Claude 리뷰

Claude CLI, 연결 가능한 플러그인, 브라우저 세션이 없어 읽기 전용 리뷰를 실행하지 못했습니다. 각 변경 diff와 테스트 결과는 커밋과 이 문서에 남겼습니다. Claude 접근 수단이 마련되면 수정 권한 없이 검토를 요청하고 지적과 반영 여부를 여기에 기록해야 합니다.

## F. 남은 위험과 다음 단계

서버 스키마/RLS/Edge Function 계약이 확인되지 않았습니다. 버전·tombstone이 없어 충돌을 자동 해결하지 않으며 로컬을 보존하고 표시합니다. 계정 삭제 서버 함수가 계약을 충족하지 않으면 삭제 성공으로 표시하지 않습니다. 기록이 없는 날은 금연을 증명하지 않으므로 화면에서 ‘흡연 기록 없는 날’로 표현합니다. 자동 계산 테스트와 타입/lint가 통과한 뒤 Phase 2의 독립적인 구조·성능 작업으로 진입할 수 있으나, 서버 통합과 네이티브 검증 전에는 배포하지 않습니다.

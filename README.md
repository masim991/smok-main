# SMOK

흡연 기록과 직접 확인한 금연일, 목표와 체류 알림을 관리하는 Expo React Native 앱입니다. 모바일을 1차 대상으로 개선했고 웹을 2차 대상으로 지원합니다. 현재 작업 브랜치는 `upgrade/release-readiness`입니다.

## 로컬에서 테스트

Node.js 22 LTS와 npm을 설치한 환경에서 프로젝트 폴더를 엽니다.

```sh
npm ci
npm run build:local
npm run serve:local
```

`http://127.0.0.1:8082`를 열고 **로컬 테스트 시작**을 누릅니다. 실제 계정을 만들지 않고 기록·목표·통계·설정을 확인할 수 있습니다. 테스트 기록은 실제 계정 저장소와 분리됩니다. 서버 요청, 실제 세션 복원, 위치 권한 요청과 백그라운드 추적은 이 모드에서 실행하지 않습니다. 로컬 테스트에서는 실제 알림 예약·GPS·네이티브 지도를 검증할 수 없습니다.

모바일 개발 서버는 `npm run dev:local`로 실행합니다. 현재 명령은 localhost에 연결하므로 에뮬레이터/USB 연결 설정이 필요합니다. 실제 휴대전화에서 확인할 때에는 별도로 개발 빌드와 기기 연결을 준비해야 합니다. `.vscode/tasks.json`에 실행·빌드·검사 작업이 등록되어 있습니다.

일반 빌드와 로컬 테스트 빌드는 캐시를 비우고 따로 생성합니다. 동시에 실행하지 마세요. `npm run build:bundles`는 Android·iOS·웹의 일반 번들을 생성하고 세 플랫폼에서 로컬 테스트가 꺼졌는지 확인합니다.

## 품질 확인

```sh
npm run typecheck
npm test
npm run lint
npm run build:bundles
npx expo install --check
```

GitHub Actions도 같은 코드 검사를 수행합니다. 네이티브 JavaScript/Hermes 번들 생성은 APK·AAB·IPA 설치 및 실기기 검증과 구분해야 합니다.

## 현재 데이터 처리

- 계정별 저장소와 저장 실패 시 원본 보존, 오프라인 변경 재시도, 삭제 표시를 지원합니다.
- 날짜는 기기의 현지 날짜 기준입니다. 원격 기록은 1,000개 제한에 잘리지 않도록 전체 페이지를 읽습니다.
- 금연일은 `[checkin:smoke-free]` 직접 확인 기록과 해당 날짜 흡연량이 0인 완료된 날짜만 계산합니다. 미기록·당일·미래 날짜를 금연일로 계산하지 않습니다.
- 체류·음성·움직임만으로 흡연을 자동 기록하지 않습니다. 미검증 오디오·웨어러블 설정과 동작하지 않는 시뮬레이션 설정을 사용자 화면에서 제거했습니다.
- 과거 소유자가 기록되지 않은 공용 저장 자료는 보존하며 계정에 자동으로 가져오지 않습니다. 기존 완료 목표의 상태도 자동 변경하지 않습니다.

실행 앱은 `app/`, 활성 공급자는 `contexts/`와 `components/contexts/DataContext.tsx`입니다. `components/app/`과 일부 중복 컨텍스트는 이전 프로토타입이며 실행 경로에 포함되지 않습니다.

## 서버 연결과 출시는 다음 단계

이번 작업에서는 사용자 요청에 따라 운영 서버·EAS·스토어 설정, DB 변경, 배포, GitHub push를 수행하지 않았습니다. 공개 Supabase 클라이언트 설정은 기존 값을 유지하고 `.env.example`의 환경변수로 덮어쓸 수 있습니다. `service_role` 키는 앱에 넣으면 안 됩니다.

`supabase/migrations/202610130001_tracking.sql`은 새 환경 기준의 스키마와 권한 정책입니다. 기존 테이블의 타입·제약조건·기기 ID 기반 구역 소유권을 먼저 확인하고, 데이터를 보존하는 별도 이전 계획을 세운 뒤 staging에 적용하세요. 기존 앱 소유 테이블의 정책을 교체하므로 공유 서버에 무작정 적용하면 안 됩니다. 사용자 삭제용 `supabase/functions/delete-user/index.ts`는 검증된 토큰의 사용자만 삭제하고 DB의 소유자 외래키 cascade 설정을 전제로 합니다.

`npm run check:release`는 현재 **실패가 정상**입니다. 출시 식별자·공개 개인정보처리방침 및 삭제 요청 URL·실제 DB 권한/계정 삭제 검증·서명된 빌드·실기기 확인·남은 보안 취약점 해결이 필요합니다. Android release에 기본 debug 키를 사용하지 않도록 수정했으며 실제 서명 키는 아직 설정하지 않았습니다.

SDK 54 호환 패치와 localization 버전 불일치를 수정했습니다. 최신 stable SDK로의 단계별 전환과 남은 의존성 취약점 검토, 네이티브 프로젝트 재생성/차이 검토는 별도 출시 작업입니다. 현재 코드를 출시 승인 완료 상태로 간주하지 마세요.
